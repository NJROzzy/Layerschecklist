Python Fundamentals

These are the Python concepts that show up constantly in AI, ML, and DL work — and just as importantly, the ones you should be comfortable explaining during a technical interview.

The goal is not to memorize syntax. The goal is to understand what the code is doing well enough that you can explain it, modify it, debug it, and write a small version of it under pressure.

Interview mindset:

For every concept below, ask yourself three questions: What does it do? Why would I use it? What happens if I change it?

Lists & list comprehensions

Lists store ordered collections of values. In ML code, they appear in preprocessing, filtering, batching, feature construction, and quick data transformations.

Interview check: Be able to convert a normal loop into a list comprehension and explain when readability is more important than making the code shorter. 

squares = [x**2 for x in range(5)]

# Same idea written normally:
squares = []

for x in range(5):
    squares.append(x**2)
Dictionaries

Dictionaries store information as key-value pairs. They are everywhere in ML projects: configurations, label mappings, model outputs, hyperparameters, and experiment results.

Interview check: Know how to access, update, loop through, and safely retrieve dictionary values using .get(). 

config = {
    "lr": 0.001,
    "epochs": 10
}

print(config["lr"])

config["epochs"] = 20

batch_size = config.get("batch_size", 32)
Tuples & unpacking

Tuples often represent fixed groups of values. Unpacking lets you pull those values apart cleanly.

This appears constantly when working with tensor shapes, model outputs, datasets, and function returns.

Interview check: Understand why batch_size, channels, height, width = x.shape is useful and what error occurs if the number of values does not match. 

shape = (32, 3, 224, 224)

batch_size, channels, h, w = shape

print(batch_size)
# 32
Functions & default arguments

Functions organize reusable logic. Training loops, preprocessing steps, evaluation functions, and model utilities are usually built from small reusable functions.

Interview check: Be able to explain parameters, return values, default arguments, and why mutable default arguments can be dangerous. 

def train(model, epochs=10, lr=0.001):
    print(f"Training for {epochs} epochs")
    print(f"Learning rate: {lr}")
*args and **kwargs

*args collects extra positional arguments. **kwargs collects extra named arguments.

They are useful when building flexible ML APIs, custom layers, wrappers, and reusable training utilities.

Interview check: Be able to explain the difference between positional arguments and keyword arguments. 

def example(*args, **kwargs):
    print(args)
    print(kwargs)

example(1, 2, lr=0.001, epochs=10)
Classes & __init__

Classes let us group data and behavior together. In deep learning, models are usually represented as objects.

In PyTorch, models inherit from nn.Module, layers are usually created inside __init__, and the computation is defined inside forward().

Interview check: Be able to explain what self, __init__, inheritance, and super() are doing. 

class Net(nn.Module):

    def __init__(self):
        super().__init__()
        self.fc = nn.Linear(10, 1)

    def forward(self, x):
        return self.fc(x)
Loops with enumerate()

enumerate() gives you both the position and the value while looping.

In ML, this is common when iterating through batches, epochs, predictions, or layers.

Interview check: Know why enumerate() is usually cleaner than manually maintaining a counter. 

losses = [0.9, 0.6, 0.3]

for epoch, loss in enumerate(losses):
    print(epoch, loss)
zip()

zip() lets you loop through multiple collections together.

This is useful when pairing predictions with labels, features with values, or multiple datasets.

Interview check: Know what happens if the collections have different lengths. 

predictions = [1, 0, 1]
labels = [1, 1, 1]

for pred, label in zip(predictions, labels):
    print(pred, label)
Lambda functions

Lambda functions are small anonymous functions used when a full function definition would be unnecessary.

Interview check: Know the syntax, but also know when a normal function would be more readable. 

numbers = [1, 2, 3, 4]

squares = list(map(lambda x: x**2, numbers))
Exception handling

Real ML pipelines fail: missing files, invalid inputs, corrupt samples, bad API responses, and shape mismatches all happen.

Interview check: Understand try, except, and why catching every error with a bare except is usually a bad idea. 

try:
    value = int(user_input)

except ValueError:
    print("Input must be a number.")
Decorators

Decorators modify or wrap the behavior of a function without rewriting the function itself.

In PyTorch, @torch.no_grad() is commonly used during evaluation because gradients are not needed.

Interview check: You do not always need to implement a decorator from scratch, but you should understand what the @ syntax means. 

@torch.no_grad()
def evaluate(model, x):
    return model(x)
Iterators & generators

Generators produce values one at a time instead of storing everything in memory at once.

This idea matters when working with large datasets and data loading pipelines.

Interview check: Be able to explain why yield can use less memory than returning one huge list. 

def batches(data, batch_size):

    for i in range(0, len(data), batch_size):
        yield data[i:i + batch_size]
Sets

Sets store unique values. They are especially useful when you need fast membership checks or want to remove duplicate values.

Interview check: Know when a set is better than a list, especially when repeatedly checking whether an item already exists. 

labels = [1, 2, 2, 3, 3, 3]

unique_labels = set(labels)

print(unique_labels)
# {1, 2, 3}

if 2 in unique_labels:
    print("Found")
Mutability & references

Some Python objects can be changed after they are created. Lists and dictionaries are mutable, while integers, strings, and tuples are immutable.

Variables in Python refer to objects. Assigning one list to another variable does not automatically create a new independent list.

Interview check: Be able to explain why changing b below also changes a. 

a = [1, 2, 3]

b = a
b.append(4)

print(a)
# [1, 2, 3, 4]

# Create a separate shallow copy:
c = a.copy()
== vs is

== asks whether two objects have equal values. is asks whether they refer to the exact same object.

Interview check: Never describe is as simply another version of ==. They answer different questions. 

a = [1, 2, 3]
b = [1, 2, 3]

print(a == b)
# True

print(a is b)
# False

c = a

print(a is c)
# True

Know the Cost of Your Code

Good Python interviews are not only about whether your code works. You may also be asked how efficiently it works.

You do not need to memorize the complexity of every Python operation, but you should understand the common ones well enough to choose the right data structure.

List membership

Checking whether something exists in a list may require Python to scan through the list until it finds the value. 

x in my_list

# Usually O(n)
Dictionary lookup

Dictionaries use hashing, so looking up a key is very fast on average. 

config["lr"]

# Average case: O(1)
Set membership

Sets also use hashing, which makes checking whether a value exists very fast on average. 

x in my_set

# Average case: O(1)

The Standard You Want

You are interview-ready when you can do more than recognize Python syntax.

Given a short piece of code, you should be able to:

  • Explain what it does line by line.
  • Predict its output before running it.
  • Find bugs and edge cases.
  • Rewrite it more clearly.
  • Explain why you chose one data structure over another.
  • Estimate the basic time and memory cost of your approach.
  • Connect the Python concept to how it appears in ML code.
  • Modify the code when the interviewer changes the requirements.

Do not aim to memorize Python. Aim to understand it well enough to reason with it.
