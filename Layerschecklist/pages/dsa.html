Data Structures & Algorithms

DSA shows up less in day-to-day ML work and more in interviews — but it's also the foundation for writing efficient code once your dataset gets too big to brute-force through.

Interview mindset:

For every problem: What's the brute-force solution? What's the time/space complexity? Can a different data structure do better?

Big O Notation

Describes how runtime or memory grows as input size grows — independent of hardware.

Interview check: Identify O(1), O(log n), O(n), O(n log n), O(n²) from loop structure. 

# O(n)
for x in arr:
    print(x)

# O(n^2)
for x in arr:
    for y in arr:
        print(x, y)
Hash Maps

Store key-value pairs with near-instant lookup, insertion, and deletion — a go-to tool for optimizing brute-force solutions.

Interview check: Explain why "have I seen this?" is O(1) with a hash map vs. O(n) with a list. 

seen = {}

for num in nums:
    if num in seen:
        print("duplicate:", num)
    seen[num] = True
Stacks & Queues

A stack is Last-In-First-Out. A queue is First-In-First-Out.

Interview check: Know a use case for each — stacks for backtracking, queues for breadth-first search. 

stack = []
stack.append(1)
stack.pop()

from collections import deque
queue = deque()
queue.append(1)
queue.popleft()
Trees & Binary Search Trees

A hierarchical structure of nodes. A BST keeps values ordered so search, insert, and delete average O(log n).

Interview check: Explain why an unbalanced BST degrades to O(n). 

class TreeNode:
    def __init__(self, value):
        self.value = value
        self.left = None
        self.right = None
Graphs & Traversal

Nodes connected by edges, used to model networks and dependencies. Traversed with BFS or DFS.

Interview check: Know when to use BFS (shortest path) vs. DFS (explore deep first). 

graph = {
    "A": ["B", "C"],
    "B": ["D"],
    "C": ["D"],
    "D": []
}
Binary Search

Repeatedly splits a sorted search space in half — O(log n) instead of checking every element.

Interview check: Know the array must be sorted first, and trace pointer movement by hand. 

def binary_search(arr, target):
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        elif arr[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

DSA Interview Questions You Should Be Able to Answer

  • What is Big O notation and why does it matter?
  • What is the time complexity of common operations on a list vs. a hash map?
  • When would you use a stack instead of a queue?
  • What is the difference between BFS and DFS?
  • What happens to BST performance if it becomes unbalanced?
  • Why must an array be sorted before binary search?
  • What is the time complexity of binary search?

The Standard You Want

You should be able to state the time/space complexity of your own solution without being asked, and explain the tradeoff of any data structure you choose.

Working code isn't enough. Know why it's efficient — or isn't.
