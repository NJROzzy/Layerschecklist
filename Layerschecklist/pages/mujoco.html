MuJoCo

MuJoCo (Multi-Joint dynamics with Contact) is a physics engine built for fast, accurate simulation — widely used to train robotics and reinforcement learning models before ever touching real hardware.

Interview mindset:

For every simulation: What's being modeled physically? What forces or contacts matter? How does a simulated result translate to reality?

The XML Model

A MuJoCo simulation is defined declaratively in XML — bodies, joints, and physical properties are described rather than coded imperatively.

Interview check: Know that this declarative approach makes it easy to swap or tweak a robot's physical design without touching simulation code. 

<mujoco>
  <worldbody>
    <body name="box" pos="0 0 1">
      <geom type="box" size="0.1 0.1 0.1"/>
    </body>
  </worldbody>
</mujoco>
Simulation Steps

Physics is advanced in small discrete timesteps — each call integrates forces, velocities, and positions forward by a tiny amount.

Interview check: Know why smaller timesteps improve accuracy but cost more compute. 

import mujoco

mujoco.mj_step(model, data)
Actuators & Sensors

Actuators apply forces/torques to joints (like motors). Sensors read back state (position, velocity, contact forces) for the controller to use.

Interview check: Know the basic control loop: read sensor → decide action → apply actuator → step simulation. 

data.ctrl[0] = 1.0  # apply actuator force
mujoco.mj_step(model, data)
print(data.sensordata)

MuJoCo Interview Questions You Should Be Able to Answer

  • Why use a physics simulator instead of testing directly on real hardware?
  • What is the tradeoff of smaller vs. larger simulation timesteps?
  • What's the difference between an actuator and a sensor in a simulation?
  • What's the "sim-to-real gap," and why does it matter?

The Standard You Want

You should understand simulation not just as a way to test code, but as a tool for generating cheap, safe training data for robotics ML models.

A good simulation saves you from breaking real, expensive hardware.
